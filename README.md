# DiscordOnline

Минималистичный веб-клон Discord для компании до **5 друзей**: голосовой чат (WebRTC mesh + Opus), демонстрация экрана, текстовый чат и аватарки — без регистрации, баз данных и лишней сложности.

## Возможности

- **Комнаты до 5 человек:** вход по нику и коду комнаты (или прямой ссылке `/room/abc123`). Шестому участнику показывается понятное сообщение, что комната заполнена.
- **Опциональный пароль:** задаётся через переменную окружения `ROOM_PASSWORD`.
- **Голосовой чат (WebRTC mesh, Opus):**
  - Настроенный SDP для Opus (~112 kbps, `useinbandfec=1`, `usedtx=0`, моно, 48 kHz).
  - Переключатели `echoCancellation`, `noiseSuppression`, `autoGainControl`.
  - Выбор микрофона и устройства вывода (`setSinkId`), кнопки Mute / Deafen, индивидуальная громкость для каждого участника, индикатор говорящего (`AudioContext` + `AnalyserNode`).
  - Режим Push-to-Talk с настраиваемой клавишей.
- **Демонстрация экрана:**
  - `getDisplayMedia` (с системным звуком, где поддерживается браузером).
  - Настройки качества: `720p`/`1080p`, `30`/`60` fps, `contentHint` (`motion` для игр/видео, `detail` для текста/кода).
  - Адаптация битрейта в зависимости от количества зрителей (1–4).
  - Одновременно может шарить только один человек; для зрителей есть кнопка «На весь экран».
- **Аватарки:** загрузка, обрезка и ресайз в браузере до `128×128` (WebP/JPEG ≤ 50 КБ), хранение в `localStorage`. Если аватарки нет — цветной круг с инициалами по хэшу ника.
- **Текстовый чат:** реальное время, история последних 100 сообщений в памяти сервера, кликабельные ссылки, вставка картинок из буфера (`Ctrl+V`), защита от XSS и rate-limit.

## Локальный запуск

Требуется **Node.js ≥ 20** и **npm**.

1. Установите зависимости в корне, на сервере и на клиенте:
   ```bash
   npm install
   npm --prefix server install
   npm --prefix client install
   ```
2. Скопируйте `.env.example` в `.env` (опционально, для пароля или TURN):
   ```bash
   cp .env.example .env
   ```
3. Запустите в режиме разработки:
   ```bash
   npm run dev
   ```
   - Клиент (Vite): `http://localhost:5173`
   - Сервер (Express + Socket.IO): `http://localhost:3001`

### Сборка и запуск в production-режиме
```bash
npm run build
npm run start
```
Сервер сам раздаст собранный фронтенд из `client/dist` на порту `PORT` (по умолчанию `3001`).

### Проверка с телефона или с другом (HTTPS-туннель)
Браузеры разрешают `getUserMedia` (микрофон) только на `localhost` или по **HTTPS**. Чтобы протестировать локальный сервер с телефона или с другом по сети:

- **Cloudflare Tunnel (без регистрации):**
  ```bash
  npx cloudflared tunnel --url http://localhost:5173
  ```
- **или ngrok:**
  ```bash
  ngrok http 5173
  ```
Откройте выданную `https://...` ссылку.

## Настройка TURN-сервера (важно!)

Без TURN-сервера часть пользователей за строгим NAT / корпоративным или мобильным интернетом не сможет установить WebRTC-соединение. По умолчанию используются публичные STUN-серверы Google.

### Вариант 1: Metered.ca Open Relay (бесплатный тариф)
1. Зарегистрируйтесь на [metered.ca/tools/openrelay](https://www.metered.ca/tools/openrelay/) (или в панели Metered TURN).
2. Получите `TURN_URL` (например, `turn:a.relay.metered.ca:80,turns:a.relay.metered.ca:443?transport=tcp`), `TURN_USERNAME` и `TURN_CREDENTIAL`.
3. Впишите их в `.env` (локально) или в Environment Variables на Render.

### Вариант 2: Cloudflare Calls TURN
1. В личном кабинете Cloudflare откройте **Calls → TURN**.
2. Создайте TURN-ключ и используйте выданные `urls`, `username` и `credential` в переменных `TURN_URL`, `TURN_USERNAME`, `TURN_CREDENTIAL`.

## Деплой (бесплатный хостинг)

### Основной вариант: Render.com Free Web Service
В корне репозитория уже лежит [`render.yaml`](./render.yaml).

1. Залейте код в репозиторий на GitHub:
   ```bash
   git remote add origin https://github.com/<ВАШ_ЛОГИН>/discord-online.git
   git push -u origin main
   ```
2. На [render.com](https://render.com) нажмите **New → Blueprint** (или **New → Web Service**) и подключите ваш GitHub-репозиторий.
3. Render автоматически подхватит `render.yaml` (команда сборки `npm install && npm --prefix server install && npm --prefix client install && npm run build`, запуск `npm run start`).
4. В разделе **Environment** задайте при необходимости:
   - `ROOM_PASSWORD` — общий пароль для входа в комнаты (если не нужен, оставьте пустым).
   - `TURN_URL`, `TURN_USERNAME`, `TURN_CREDENTIAL` — ключи TURN.
5. После деплоя откройте публичный URL вида `https://discord-online.onrender.com`.

> **Важно про Free-тариф Render:** бесплатный инстанс засыпает после ~15 минут без активности. Первый заход после простоя занимает около **40–60 секунд** (пока сервер просыпается) — это нормально для бесплатного тарифа.

### Запасные варианты: Fly.io / Railway
- **Railway:** подключите GitHub-репозиторий, укажите Build Command `npm install && npm --prefix server install && npm --prefix client install && npm run build`, Start Command `npm run start`, добавьте переменные окружения.
- **Fly.io:** выполните `fly launch` (Node.js), добавьте секреты через `fly secrets set ROOM_PASSWORD=... TURN_URL=... TURN_USERNAME=... TURN_CREDENTIAL=...` и задеплойте `fly deploy`.

## Известные ограничения

- **Максимум 5 человек** в комнате (WebRTC mesh: при большем числе участников резко растёт нагрузка на канал и CPU, особенно при демонстрации экрана).
- **Нет БД:** история последних 100 сообщений и текущие комнаты хранятся только в оперативной памяти сервера и сбрасываются при его перезапуске.
- **Мобильный Safari / iOS:** выбор устройства вывода звука (`setSinkId`) и демонстрация экрана с системным звуком зависят от поддержки конкретным браузером.
- **Аватарки** хранятся в `localStorage` браузера (при очистке данных браузера нужно загрузить заново).

- Звуковые уведомления при входе/выходе участника и при новом сообщении в чате.
- Индикатор качества соединения (RTT / потери пакетов из `RTCPeerConnection.getStats()`).
